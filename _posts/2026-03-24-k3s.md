# From Docker Compose to k3s

It's been about 18 months since the last post (the Cisco AP saga). A lot has changed in the lab since then — the Cisco gear is gone entirely, replaced with a pure UniFi network which has been a breath of fresh air. But the biggest change deserved its own writeup: I finally ripped out the Docker Compose setup and moved everything to k3s.

## Why

The homelab has been running on Docker Compose across a couple VMs for a while now. It worked, until I realized my "infrastructure" was a bunch of docker-compose files scattered across filesystems, secrets in plaintext .env files, and a disaster recovery plan that consisted of "I think I remember where everything is". There was no single source of truth for what was running, no way to roll back a bad change without SSH'ing in and praying, and monitoring was basically nonexistent.

I wanted GitOps, real observability, and something I could eventually grow into multi-node. k3s fit the bill without the overhead of full fat kubernetes.

## The Hardware

Single k3s node right now, running as a VM on the DL380 under Proxmox:

- **k3s node** (192.168.1.225): Ubuntu 24.04, 8 vCPU, 48GB RAM, 242GB disk
- **Control plane VIP**: 192.168.1.230 (kube-vip)
- **Load balancer pool**: 192.168.1.231-240 (MetalLB, L2 mode)

Storage is Longhorn for block (default StorageClass) and NFS mounts back to the TrueNAS box for media and backups. Longhorn backups also target TrueNAS.

## GitOps

Everything lives in one repo. Flat layout — one directory per stack under `stacks/`, one ArgoCD Application per stack under `apps/`. Root app-of-apps auto-discovers everything. Push to main, ArgoCD syncs. Done.

Secrets are Sealed Secrets — encrypted at rest in git, decrypted in-cluster. Private key backed up offline. No more .env files.

## DNS

This took some figuring out. Two ExternalDNS instances:

1. **Technitium** (RFC2136/TSIG): Watches all IngressRoutes, creates A records pointing to Traefik's MetalLB IP for internal resolution
2. **Cloudflare**: Watches only annotated IngressRoutes, creates CNAMEs for public-facing services

Traefik does ingress with a wildcard cert from cert-manager (Let's Encrypt, Cloudflare DNS challenge). A DDNS pod keeps the root domain A record updated. Internal clients hit Technitium via conditional forwarding on the UDMP.

The end result is you deploy a service, slap the right annotations on the IngressRoute, and DNS just works — internally and externally. Want it public? Add `cloudflare-proxied: "true"`. That's it.

## What's Running

About a week of migration work got all of this into the cluster:

**Core Infra**: ArgoCD, Traefik, cert-manager, MetalLB, kube-vip, Longhorn, Sealed Secrets, Rancher

**Media**: Radarr, Sonarr, Prowlarr, Tautulli, Ombi — all sharing NFS media mounts. TVHeadend (hostNetwork for tuner access) and ErsatzTV.

**Apps**: Vaultwarden with a backup sidecar that dumps to NFS, Tandoor Recipes (postgres backend), RomM with MariaDB and an NFS game library, Homepage dashboard, Uptime Kuma, Spoolman, Earthwalker, Scribble

**Games**: Minecraft Forge 1.16.5 and Satisfactory dedicated servers on their own MetalLB IPs. Both sit at `replicas: 0` by default so they're not eating resources when nobody's playing.

**The fun stuff**: Massive Decks (Cards Against Humanity clone — nginx frontend, node backend, postgres), a custom Jeopardy app (Node.js + Redis, loads 8903 episodes into memory, it's a chonker), and a Home Assistant proxy (headless service pointing at the HA box on the LAN)

## Monitoring

This is where the upgrade from compose really shows. Going from "I think that container is up" to actual observability:

- **Prometheus** — 90 day retention, scraping nodes, pods, Traefik, Longhorn, ArgoCD, plus external targets: UniFi gateway, Proxmox, Technitium, iLO via Redfish, Windows DCs, TrueNAS
- **Grafana** — 21+ provisioned dashboards, no more manual imports after a rebuild
- **Loki + Promtail** — centralized logs, 30 day retention
- **Falco** — runtime threat detection with modern eBPF, Falcosidekick web UI
- **Trivy Operator** — vulnerability scanning, config audits, RBAC assessment
- **CrowdSec** — watching Traefik logs for sketchy traffic

## Patterns Worth Mentioning

**ConfigMap + PVC seed**: For apps that need writable config at runtime (Homepage, Minecraft, RomM) there's a ConfigMap as the git-managed source of truth, an init container that copies it into a Longhorn PVC on start, and Stakater Reloader watching for changes to auto-restart the pod. Git-managed config that the app can still scribble on.

**NFS for shared data, Longhorn for everything else**: Media libraries mount as ReadOnlyMany NFS. Databases and app configs get their own Longhorn PVCs. Backups go back to TrueNAS either way.

## Lessons Learned

**kube-vip lease timers are way too aggressive for single-node.** The defaults assume multi-node failover. On one node the VIP flaps because the lease renewal races against itself. Crank `--leaseDuration`, `--leaseRenewDeadline`, and `--leaseRetryPeriod` way up if you're solo. I spent an embarrassing amount of time watching the API server go up and down before I figured this one out.

**Service naming will bite you.** Kubernetes injects env vars for every service in the namespace. Name a service `spoolman` and suddenly there's a `SPOOLMAN_PORT` that conflicts with what the app expects. Had to rename to `spoolman-svc`. Ask me how long that took to figure out.

**ExternalDNS sync policy deletes what it doesn't manage.** Running `--policy=sync` (which you want for cleanup) means every IngressRoute needs the `target` annotation or ExternalDNS will nuke records it didn't create. Found that out when internal DNS went sideways for about 10 minutes.

**RomM breaks behind Cloudflare proxy.** SPA integrity checks fail when Cloudflare rewrites responses. DNS-only mode fixes it. Not immediately obvious from the error messages.

**TVHeadend needs hostNetwork.** No clean way to pass through DVB tuner devices without it. Pair with `dnsPolicy: ClusterFirstWithHostNet` or you lose cluster DNS resolution. That second part isn't in most guides and will leave you scratching your head when the container can't resolve anything.

**ErsatzTV will exhaust inotify watches.** Default limit of 128 gets blown away by media library scanning. Bumped to 512 on the node. The pod just silently stops picking up new files until you do.

**Sealed Secrets key management is critical.** If you lose the private key, every sealed secret in the repo becomes unrecoverable garbage. Back it up offline before you seal anything important. This should be step one, not something you remember to do later.

**The flat stack layout was the right call.** I went back and forth on nested directories, namespaces-as-folders, all kinds of structure. One stack = one directory = one ArgoCD app ended up being the simplest thing that works. Easy to reason about, easy to add new stuff, no framework to fight.

## Was It Worth It

Yeah. Took about a week and now everything is version controlled, observable, and reproducible. Node dies? Clone the repo, stand up k3s, point ArgoCD at it, reseal the secrets, everything comes back. Beats the hell out of SSHing into a box and grepping through docker-compose files trying to figure out what went wrong.
